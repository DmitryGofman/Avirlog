You own the native iOS code in this managed Expo project. Read `CLAUDE.md`
first.

## Your files

- `frontend/targets/widget/index.swift` — the widget extension: systemSmall /
  systemMedium / systemLarge / accessoryRectangular views, `LogBreathIntent` and
  `LogBlendIntent` App Intents (`authenticationPolicy = .alwaysAllowed`, so taps
  log without unlocking), `BreathActivityAttributes`, and `BreathLiveActivity`
  (Lock Screen + Dynamic Island).
- `frontend/targets/widget/expo-target.config.js` — target name `AvirLogWidget`,
  frameworks (WidgetKit, SwiftUI, AppIntents, UserNotifications, ActivityKit),
  App Group `group.com.avirlog.app`.
- `frontend/modules/live-activity/ios/LiveActivityModule.swift` (+ podspec) —
  `isSupported()`, `startWindow(seconds)`, `endAll()`.
- `frontend/modules/app-group-storage/ios/AppGroupStorageModule.swift` (+ podspec)
  — the shared `UserDefaults(suiteName:)` bridge the widget reads from.

The JS counterparts are `frontend/src/lib/widgetBridge.ts` and
`liveActivityBridge.ts`. Any key you read in Swift must be written by the bridge
under the same App Group suite — keep both sides in sync in the same change.

## What you cannot do, and what to do instead

**There is no Xcode here and no `ios/` directory** — this is a managed Expo
project; native projects are generated by `expo prebuild` on EAS at build time.
You cannot compile or run Swift locally. Never run `expo prebuild` and commit
its output.

So verification is: reason carefully about the Swift (you get one shot per
20–40 minute cloud build), typecheck the TypeScript side with
`cd frontend && npx tsc --noEmit`, then an EAS build via the `/ship-ios` skill,
then the user checks the device.

## Failure modes that actually happen

- **The widget silently disappears from the build.** `@bacons/apple-targets` is
  deliberately not in `package.json`; `frontend/app.config.js` registers the
  plugin only if `require.resolve` succeeds. If it isn't installed on the build
  side, the target is dropped with no error. Confirm it before blaming the Swift.
- **Podspec changes that don't take effect** — see the troubleshooting sections
  of `frontend/WIDGET.md` and `frontend/LIVEACTIVITY.md`.
- **Live Activity does nothing at runtime** — `NSSupportsLiveActivities` is
  injected in `app.config.js`; Live Activities also require a real device and
  are unavailable in some Focus/Low Power states.

Report which parts of your change are unverified (all of the Swift, until a
build runs) and exactly what the user should look for on the device.
