# AvirLog — Claude Code Project Guide

AvirLog is a breath-awareness / nostril-dominance journal (Swara Yoga framing).
What ships to the App Store is the **frontend only, in local-only mode** — no
account, no backend calls, all data on-device.

## Repo map

| Path | What it is |
|---|---|
| `frontend/` | Expo (React Native) app, SDK 54, expo-router, TypeScript. The product. |
| `backend/` | FastAPI + MongoDB (`backend/server.py`). Optional; NOT used by the shipped app. |
| `prototypes/` | Standalone HTML design prototypes + research docs. Reference only. |

Key runbooks (manual-side source of truth — do not duplicate their content):
`SUBMIT_STEPS.md` (App Store submission), `RELEASE_CHECKLIST.md` (pre-flight +
App Review blind spots), `STORE_LISTING.md` (store copy), `frontend/WIDGET.md`
and `frontend/LIVEACTIVITY.md` (native target build/verify loops).

## iOS invariants — do not break these

- **Managed Expo workflow.** There is no `ios/` directory and there must never
  be one committed. Native projects are generated by `expo prebuild` on EAS at
  build time. Never run `expo prebuild` and commit the result.
- **`@bacons/apple-targets` is intentionally NOT in `package.json`.**
  `frontend/app.config.js` registers the plugin only if `require.resolve`
  succeeds. It must be installed on the build side (`npx expo install
  @bacons/apple-targets`) or the widget silently drops out of the build. Do not
  "fix" this by adding it to `package.json` without testing an EAS build.
- **Native Swift lives in three places:** `frontend/targets/widget/index.swift`
  (WidgetKit widget + App Intents + Live Activity),
  `frontend/modules/live-activity/ios/`, `frontend/modules/app-group-storage/ios/`
  (each with a podspec). Swift cannot be compiled in this container — only an
  EAS build verifies it.
- **`experiments.baseUrl` is web-only.** `app.json` sets it to `/Avirlog` for
  GitHub Pages, and `app.config.js` strips it unless `EXPO_WEB_BASE_URL` is set.
  Leaving it applied on native crashes the asset-copy step of an iOS build
  (`ENOTDIR`). Never set `EXPO_WEB_BASE_URL` for a store build.
- **Identifiers:** bundle ID `com.avirlog.app`, App Group `group.com.avirlog.app`
  (injected in `frontend/app.config.js`). Version in `frontend/app.json`;
  build numbers are EAS-remote (`autoIncrement: true`).
- **Build stamp:** bump `CODE_REVISION` in `frontend/src/lib/buildInfo.ts`
  (e.g. "r5" → "r6") whenever shipping a new build. Surfaced in Settings → About.
- **Local-only mode:** `ACCOUNTS_ENABLED` stays `false`
  (`frontend/src/lib/config.ts`) and `EXPO_PUBLIC_BACKEND_URL` must NOT be set
  for store builds.
- **Store copy / in-app wording:** health-claim safe language only —
  "observe / log / notice", never "treat / heal / cure".

## Verification commands (work in this container)

```bash
cd frontend
yarn install          # first time only
npx tsc --noEmit      # must print nothing
npx expo-doctor       # env/config sanity
npx expo export --platform web   # smoke build (no iOS binary needed)
```

iOS binaries build on EAS cloud (`eas build --platform ios`), which works from
Linux when `EXPO_TOKEN` is set. On-device verification (TestFlight) always
requires the user.

## Releasing

Use the **`/ship-ios` skill** (`.claude/skills/ship-ios/`). It runs preflight,
detects which credentials are available, builds and submits non-interactively
as far as possible, and hands the user an exact manual-step list for the rest.

## Agent team — when to delegate

| Agent | Use for |
|---|---|
| `mobile-developer` | Expo/React Native/TypeScript feature work in `frontend/` |
| `ios-native` | Swift: widget, Live Activity, App Intents, native modules/podspecs |
| `qa-reviewer` | Verifying changes (typecheck/lint/smoke build) + App Review compliance review |
| `release-manager` | Driving a release end-to-end via `/ship-ios` |

Typical flow for "add feature X and ship it": `mobile-developer` (and
`ios-native` if Swift is touched) implement → `qa-reviewer` verifies →
`/ship-ios` (or `release-manager`) builds and submits → user gets the
remaining Mac/iPhone steps.
